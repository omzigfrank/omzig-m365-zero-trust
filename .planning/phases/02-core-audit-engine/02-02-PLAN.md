       - `pushAuditProgress(userId: string, message: AuditProgressMessage): Promise<void>`:
         - Reads SIGNALR_ENDPOINT and SIGNALR_ACCESS_KEY from env
         - Constructs URL: `${endpoint}/api/v1/hubs/audit/users/${userId}`
         - Signs JWT with accessKey (HS256), audience = URL, expiry = 5min
         - POSTs to URL with `{ target: 'auditProgress', arguments: [message] }`
         - Hub name: 'audit' (Claude's discretion per CONTEXT.md)

       - `negotiateSignalR(userId: string): { url: string; accessToken: string }`:
         - Constructs hub URL: `${endpoint}/client/?hub=audit`
         - Signs JWT with userId as `nameid` claim, audience = hubUrl, expiry = 1hr
         - Returns { url: hubUrl, accessToken: signed JWT }

    1. Create `apps/api/src/routes/audits.ts` as a Hono sub-application with these routes:

       **POST /tenants/:tenantId/audits** (trigger audit):
       - Uses `withTenantDb()` middleware for tenant context
       - Uses `requireRole('Analyst')` or equivalent (Analyst can trigger audits)
       - Accepts optional `{ accessToken?: string }` in request body (the delegated Graph token for the target tenant)
       - Creates a new audit run row in tenant DB with status='running', totalChecks=29, startedAt=now
       - Returns 202 with `{ data: { auditId, status: 'running' } }`
       - IMPORTANT: Does NOT run the actual pipeline yet (Plan 03 wires `runAuditPipeline` as fire-and-forget). For now, the background task is a placeholder that marks the run as 'completed' after creation.
       - CRITICAL: The async pipeline must open its OWN tenant DB connection using `getTenantDb(databaseName)`, NOT use the middleware-provided `tenantDb` (PITFALL 4 from research -- middleware closes the connection after response). Pass the `databaseName` string to the background task.

       **GET /tenants/:tenantId/audits** (list audits):
       - Uses `withTenantDb()` middleware
       - Queries auditRuns table ordered by createdAt DESC
       - Returns `{ data: auditRuns[] }`

       **GET /tenants/:tenantId/audits/:auditId** (audit detail):
       - Uses `withTenantDb()` middleware
       - Queries auditRuns WHERE id = auditId
       - Queries auditFindings WHERE auditRunId = auditId
       - Returns `{ data: { ...auditRun, findings: auditFindings[] } }`
       - Returns 404 if auditId not found

       **POST /tenants/:tenantId/audits/:auditId/checks/:controlId/retry** (retry single check):
       - Uses `withTenantDb()` middleware
       - Uses `requireRole('Analyst')`
       - Returns 202 with `{ data: { auditId, controlId, status: 'retrying' } }`
       - Placeholder implementation (Plan 03 wires actual retry logic)
