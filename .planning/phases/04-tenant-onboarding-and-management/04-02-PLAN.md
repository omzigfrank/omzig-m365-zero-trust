  <action>
    Replace the entire contents of `apps/api/src/routes/tenants.ts` with full route implementations:

    **GET /api/tenants** (list):
    - Get jwtPayload from context, look up user by entraObjectId in users table
    - Look up user's orgId
    - Query tenants WHERE orgId = user.orgId AND isDeleted = false
    - For each tenant, query latest audit from tenant DB to get framework scores (or use lastAuditScore from tenant record as cache)
    - Map to TenantSummary array using calculateHealth()
    - Return { data: TenantSummary[], meta: { correlationId, timestamp } }
    - For the dashboard MVP, use the cached lastAuditScore and set frameworkScores to null (querying each tenant DB for scores would be too expensive -- that optimization comes when we update lastAuditScore after each audit). criticalFindingsCount also defaults to 0 until wired.

    **POST /api/tenants** (create):
    - Validate body with zod: { displayName: string (3-200 chars), primaryDomain: string (optional), contactEmail: string (optional email) }
    - Generate UUID for tenant ID
    - Insert into tenants table: id, orgId (from user), displayName, m365TenantId='' (set during provisioning), databaseName=null, tokenSecretName=null, status='pending', primaryDomain, contactEmail
    - Return 201 with { data: { id, status: 'pending' }, meta: ... }

    **GET /api/tenants/:id** (detail):
    - Query tenant by ID WHERE orgId = user.orgId AND isDeleted = false
    - Return 404 if not found
    - Map to TenantSummary, return { data: TenantSummary, meta: ... }

    **POST /api/tenants/:id/onboard/oauth** (generate consent URL):
    - Verify tenant exists and is in 'pending' status
    - Call buildConsentUrl(tenantId) from oauth-consent service
    - Update tenant connectionMethod to 'oauth'
    - Return { data: { consentUrl }, meta: ... }

    **POST /api/tenants/:id/onboard/gdap** (verify GDAP):
    - Validate body: { relationshipId: string }
    - Get MSP's access token from jwtPayload (or use the platform's own token for GDAP verification)
    - Call verifyGdapRelationship(relationshipId, accessToken) from gdap-verification service
    - Update tenant: m365TenantId = result.customerTenantId, connectionMethod = 'gdap', displayName = result.customerDisplayName (if still default)
    - Return { data: { customerTenantId, customerDisplayName, roles, expiresAt }, meta: ... }

    **POST /api/tenants/:id/provision** (create DB and activate):
    - Validate body: { m365TenantId: string, token: string, connectionMethod: 'oauth' | 'gdap' }
    - Verify tenant exists and is in 'pending' status
    - Call provisionTenant(tenantId, m365TenantId, token, userId) from provisioning service
    - Return { data: { databaseName, tenantId, status: 'active' }, meta: ... }
    - Wrap in try/catch, return 500 with PROVISIONING_ERROR on failure

    **DELETE /api/tenants/:id** (soft delete):
    - Verify tenant exists and is NOT already deleted
    - Call deprovisionTenant(tenantId) from provisioning service
    - Return { data: { id, status: 'suspended' }, meta: ... }

    Use requireRole('Admin') middleware on POST/DELETE endpoints. GET endpoints accessible to all authenticated users (subject to org filtering).
