    OAuth consent service:
    - buildConsentUrl(wizardSessionId) returns URL containing client_id, response_type=code, redirect_uri, scope, prompt=admin_consent, and HMAC-signed state parameter
    - exchangeCodeForTokens(code) calls MSAL acquireTokenByCode and returns { accessToken, tenantId, expiresOn }
    - verifyStateHmac(state) returns decoded wizardSessionId or throws on tampering
    - GRAPH_SCOPES constant contains 'https://graph.microsoft.com/.default offline_access'

    GDAP verification service:
    - verifyGdapRelationship(relationshipId, accessToken) fetches Graph API endpoint and returns { customerTenantId, customerDisplayName, roles, expiresAt }
    - Throws if relationship status is not 'active'
    - Throws descriptive error if relationship not found (404)

    Tenant provisioning service:
    - provisionTenant(tenantId, m365TenantId, token, userId) creates DB via T-SQL CREATE DATABASE with ELASTIC_POOL, runs migrateTenantDb, stores token in Key Vault, updates tenant record to 'active', grants user access
    - Returns { databaseName, tenantId }
    - deprovisionTenant(tenantId) sets isDeleted=true, deletedAt=now, status='suspended'
  </behavior>
  <action>
    First, install @azure/msal-node:
    ```bash
    pnpm add @azure/msal-node --filter @omzig/api
    ```

    **oauth-consent.ts:**
    - Import ConfidentialClientApplication from @azure/msal-node
    - Create lazy singleton CCA with config from env vars: OAUTH_CLIENT_ID, OAUTH_CLIENT_SECRET, authority = 'https://login.microsoftonline.com/organizations'
    - Export `GRAPH_SCOPES = ['https://graph.microsoft.com/.default', 'offline_access']` as constant
    - `buildConsentUrl(wizardSessionId: string): string` -- builds the authorization URL using `/organizations/oauth2/v2.0/authorize` with query params: client_id, response_type=code, redirect_uri (from env OAUTH_REDIRECT_URI), scope='https://graph.microsoft.com/.default offline_access', state=HMAC-signed JSON of {wizardSessionId, ts: Date.now()}, prompt=admin_consent. Use crypto.createHmac('sha256', OAUTH_CLIENT_SECRET) for state signing. Per RESEARCH Pitfall 1: use authorize endpoint with prompt=admin_consent (NOT the /adminconsent endpoint) to get both consent and code in one redirect.
    - `verifyStateHmac(state: string): { wizardSessionId: string }` -- decode base64 state, split payload|signature, verify HMAC, check timestamp is within 1 hour, return decoded payload. Throw on invalid/expired.
    - `exchangeCodeForTokens(code: string): Promise<{ accessToken: string; tenantId: string; expiresOn: Date }>` -- call cca.acquireTokenByCode({ code, redirectUri, scopes: GRAPH_SCOPES }). Extract tenantId from result.account.tenantId. Return { accessToken, tenantId, expiresOn }.

    **gdap-verification.ts:**
    - Export `GdapVerificationResult` interface: { customerTenantId, customerDisplayName, roles: Array<{ roleDefinitionId: string }>, expiresAt: string }
    - `verifyGdapRelationship(relationshipId: string, accessToken: string): Promise<GdapVerificationResult>` -- fetch GET `https://graph.microsoft.com/v1.0/tenantRelationships/delegatedAdminRelationships/${relationshipId}` with Bearer token. Check response.ok, throw descriptive error on 404 ('GDAP relationship not found'). Parse response JSON. Verify status === 'active' (throw if not, with helpful message per RESEARCH Pitfall 4). Return { customerTenantId: relationship.customer.tenantId, customerDisplayName: relationship.customer.displayName, roles: relationship.accessDetails.unifiedRoles, expiresAt: relationship.endDateTime }.

    **tenant-provisioning.ts:**
    - Import mssql, { getControlPlaneDb, migrateTenantDb, tenants, tenantUserAccess } from @omzig/db, { storeTenantToken } from keyvault, { eq } from drizzle-orm
    - `provisionTenant(tenantId: string, m365TenantId: string, token: string, userId: string): Promise<{ databaseName: string; tenantId: string }>`:
      1. Generate opaque DB name: `t_${crypto.randomUUID().replace(/-/g, '').slice(0, 16)}`
      2. Build mssql config for 'master' database using same buildConfig pattern from @omzig/db (import or replicate the config builder -- read connection.ts to understand the pattern, replicate the relevant config builder locally since it's not exported)
      3. Connect to master, execute: `CREATE DATABASE [${dbName}] (SERVICE_OBJECTIVE = ELASTIC_POOL (name = [${process.env.ELASTIC_POOL_NAME}]))` -- use parameterized-safe string (dbName is UUID-based, no injection risk). Close master pool in finally.
      4. Call migrateTenantDb(dbName) to apply tenant schema
      5. Call storeTenantToken(tenantId, token) to encrypt and store in Key Vault
      6. Update tenant record: set databaseName, tokenSecretName=`tenant-token-${tenantId}`, status='active', m365TenantId (if not already set)
      7. Insert tenantUserAccess row granting the onboarding user access
      8. Return { databaseName: dbName, tenantId }
    - `deprovisionTenant(tenantId: string): Promise<void>`:
      1. Get control plane DB
      2. Update tenant: set isDeleted=true, deletedAt=sql`GETDATE()`, status='suspended'
      3. Do NOT drop database or delete secrets yet (30-day retention, hard purge is out of scope per CONTEXT)
