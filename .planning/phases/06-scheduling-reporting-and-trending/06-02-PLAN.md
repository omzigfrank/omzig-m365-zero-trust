    1. Install PDFKit in API package:
       ```bash
       cd apps/api && pnpm add pdfkit svg-to-pdfkit && pnpm add -D @types/pdfkit
       ```

    2. Create `apps/api/src/services/pdf-report.ts`:
       - Import `PDFDocument` from `pdfkit`, `SVGtoPDF` from `svg-to-pdfkit`, and SVG chart functions.
       - Define `ReportData` interface: `{ tenantName, orgName, auditDate, overallScore, frameworkScores, maturitySnapshot, findings, trendData? }`.
       - Export `generateExecutiveReport(data: ReportData): Promise<Buffer>`:
         - Page 1: "Compliance Assessment Report" header, org name, tenant name, date, overall score (large text), framework score bar chart SVG.
         - Page 2: Top 5 critical/high-severity findings table (controlId, severity, message), ZTA maturity level summary.
         - Page 3 (optional): ZTA radar chart SVG if maturity data available.
         - Omzig branding: simple text header "Omzig Zero Trust Auditor" at top of page 1. Gray/blue color scheme.
       - Export `generateFullReport(data: ReportData): Promise<Buffer>`:
         - Everything from executive plus:
         - Pages 3-8: All findings grouped by framework (AAD, ZTA, 800-53, CSF). Each group shows framework name header, per-finding rows with controlId, severity badge text, rating, message, action.
         - Radar chart SVG page.
         - Trend line chart SVG page if trendData has 3+ points.
       - Buffer collection pattern: `doc.on('data', chunk => chunks.push(chunk))`, resolve on `doc.on('end')`.

    3. Add new endpoints to `apps/api/src/routes/audits.ts`:

       a. `GET /tenants/:tenantId/audits/history`:
          - Query all completed audit runs ordered by completedAt descending.
          - For each run, fetch findings using a batch query: `SELECT * FROM auditFindings WHERE auditRunId IN (...)` -- group in-memory by auditRunId (avoids N+1 per PITFALL 4 from research).
          - Compute per-framework scores: group findings by `product`, count pass/(pass+fail)*100 per product.
          - Compute overallScore: total pass / total (pass+fail) * 100 across all products.
          - Also fetch maturityScores for each run to get overall maturity level.
          - Return: `{ data: Array<{ auditId, completedAt, startedAt, status, duration (ms), totalChecks, passedChecks, failedChecks, overallScore, frameworkScores: { AAD, ZTA, '80053', CSF } }> }`.

       b. `GET /tenants/:tenantId/audits/:auditId/report`:
          - Accept query param `type` validated as 'executive' | 'full' (400 if invalid).
          - Load the audit run + findings + maturityScores from tenant DB (reuse existing detail query pattern).
          - Load tenant info from control-plane DB (displayName, org name).
          - Optionally load trend data (last 10 completed runs for trend chart in full report).
          - Call `generateExecutiveReport` or `generateFullReport` based on type.
          - Return PDF Buffer with headers: `Content-Type: application/pdf`, `Content-Disposition: attachment; filename="compliance-report-{type}-{date}.pdf"`.

       c. `GET /tenants/:tenantId/audits/:auditId/export/csv`:
          - Load audit run + findings from tenant DB.
          - Load tenant info from control-plane DB (for tenant name and ID columns).
          - Call `generateFindingsCsv(findings, run, { displayName: tenant.displayName, id: tenant.id })`.
          - Return CSV string with headers: `Content-Type: text/csv`, `Content-Disposition: attachment; filename="findings-{ISO-timestamp}.csv"`.

       d. `GET /tenants/export/csv` (multi-tenant export):
          - Resolve orgId from JWT. Query all active, non-deleted tenants for the org with non-null databaseName.
          - For each tenant, connect to its tenant DB and fetch the most recent completed audit run + its findings.
          - Call `generateMultiTenantCsv(tenantFindings)` to produce combined CSV with Tenant Name and Tenant ID as first two columns.
          - Return CSV string with headers: `Content-Type: text/csv`, `Content-Disposition: attachment; filename="all-tenants-findings-{ISO-timestamp}.csv"`.
          - If no tenants have completed audits, return 200 with header-only CSV (just the column names).

    4. Create test files:
       - `apps/api/src/__tests__/pdf-report.test.ts`: Mock pdfkit/svg-to-pdfkit, test both report types return Buffers. Test report endpoint returns 200 with application/pdf content type.
       - `apps/api/src/__tests__/audit-history.test.ts`: Mock tenant DB, test history endpoint returns correct response shape with computed scores. Test multi-tenant CSV endpoint returns text/csv content type.
