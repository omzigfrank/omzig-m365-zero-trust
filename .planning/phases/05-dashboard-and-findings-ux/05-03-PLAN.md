<objective>
Build the cross-tenant action queue: shared types, API endpoints for fetching items and dismissing them, frontend ActionQueue panel component, and wire it into the tenant dashboard page above the tenant grid.

Purpose: MSPs need a single glance to know which tenants need attention right now. The action queue surfaces critical findings and tenant status events (needs_reauth, stale audit) across all connected tenants without requiring click-through to each individual tenant. Dismiss/acknowledge prevents alert fatigue for known-but-not-yet-fixed issues.

Output: Action queue panel on /tenants with API backing, dismiss persistence, and empty state handling
</objective>

    3. Create `apps/api/src/routes/action-queue.ts`:
       - Import Hono, drizzle, schema tables (tenants, actionQueueDismissals, organizations)
       - resolveOrgId helper: reuse the same pattern from tenants.ts (extract from JWT jwtPayload variable on context)

       **GET /api/action-queue**:
       - Query all non-deleted tenants for the user's org (same pattern as GET /api/tenants)
       - For each tenant, compute action queue items:
         a. If `criticalFindingsCount > 0`: add item with type 'critical_findings', severity 'critical', message "N critical/high failures in latest audit", count = criticalFindingsCount, linkTo = `/tenants/${id}` (findings tab)
         b. If `status === 'needs_reauth'`: add item with type 'needs_reauth', severity 'high', message "Tenant needs re-authentication", linkTo = `/tenants/${id}` (settings tab)
         c. If `lastAuditAt` is more than 7 days ago (or null and tenant is active): add item with type 'stale_audit', severity 'warning', message "No audit in over 7 days", linkTo = `/tenants/${id}`
       - Query actionQueueDismissals for the current user and org
       - Overlay dismiss state: if itemKey matches, set dismissed=true
       - If query param `includeDismissed` is not 'true', filter out dismissed items
       - Sort by severity order (critical > high > warning), then by createdAt descending
       - Return `{ ok: true, data: ActionQueueItem[] }`

       **POST /api/action-queue/:itemId/dismiss**:
       - Extract itemId from params (this is the computed item ID e.g., "critical-{tenantId}")
       - Use the item ID as the `itemKey` in the dismissals table
       - Check if dismiss record already exists for (orgId, userId, itemKey) -- if so, return 200 (idempotent)
       - If not, INSERT into actionQueueDismissals with a new UUID, orgId, userId, itemKey
       - Return `{ ok: true }`

       **RBAC:** All authenticated users can read and dismiss (matches the tenant list read pattern). The action queue only shows data for tenants in the user's org.
